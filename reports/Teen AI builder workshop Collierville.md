# Ship real projects, not Claude accounts

Two high schoolers can run this workshop at Burch Library, and the research points to a specific version of it. Set the minimum age at **13** and cap enrollment at **15–20 teens**. Run **six weekly two-hour sessions** as a **library co-sponsored program**, not a room rental. Every teen builds a static web project, publishes it at a public URL, and presents it at a demo day. The biggest constraint is that **Claude's consumer product is strictly 18+**. Anthropic enforces this with under-18 detection, account disabling, and Yoti age verification, and teens have no parental-consent route ([Age assurance on Claude](https://support.claude.com/en/articles/15171100-age-assurance-on-claude)). The workable compromise is that an adult sponsor runs Claude Code on the projector as the demonstration while teens build hands-on with tools that allow ages 13 and up: GitHub and GitHub Pages, Copilot through GitHub Education, and ChatGPT with parental permission. The critical-AI goal costs no extra time. The evidence favors short, hands-on literacy work, so put a 10–15 minute "AI checkpoint" in every session where teens catch the AI's errors in their own projects. Collierville's near-universal device access allows a bring-your-own-device pilot. Memphis Public Libraries' CLOUD901 lab already serves ages 13–18 and has hosted a student-led coding workshop, so it is the natural second site. That expansion will need loaner devices and outside funding.

## Claude's 18+ rule turns it into a demo tool, not a student tool

Anthropic's Consumer Terms require users to be "at least 18 years old or the minimum age required to consent… whichever is higher" ([Anthropic Consumer Terms](https://www.anthropic.com/legal/consumer-terms)). Since 2026 Anthropic has asked suspected minors to verify their age and has disabled accounts that show signs of minor use ([Age assurance on Claude](https://support.claude.com/en/articles/15171100-age-assurance-on-claude)). Claude Code runs on a Claude subscription or an Anthropic Console account, so teens cannot hold their own Claude Code logins either. A shared organizer login used by participants breaks the terms and also risks suspension mid-session. If either organizer is under 18, neither of them can own the account. **An adult has to own any Anthropic account the workshop uses.**

Minors can reach Claude through one sanctioned route. An organization builds a product on the API and follows Anthropic's guidelines for serving minors: AI disclosure, content filtering, monitoring, a child-safety system prompt, and COPPA compliance, with Anthropic able to audit ([Guidelines for Organizations Serving Minors](https://support.claude.com/en/articles/9307344-responsible-use-of-anthropic-s-models-guidelines-for-organizations-serving-minors)). Two student organizers should not take on that compliance burden for a pilot. The more realistic adult account holder is a teacher sponsor. **Claude for Teachers** has given verified US K-12 educators free Claude access since July 2026, with sign-up open until June 30, 2027 ([Anthropic: Claude for Teachers](https://www.anthropic.com/news/claude-for-teachers)). A Collierville High School computer science teacher could hold that account and run the projector demo. Whether that program allows supervised student use was not verified, so the teacher should demo, not hand over the keyboard. Common Sense Media's March 2026 risk assessment also found that Claude is built for adults and that its responses can be too complex or mature for teens ([Common Sense Media](https://institute.commonsensemedia.org/sites/default/files/risk-assessments/csm-ai-risk-assessment-claude-03252026%20%281%29.pdf)). That supports a demo-only role.

The hands-on stack should use tools whose terms actually cover 13–17 year olds:

| Tool | Age rule | Role in the workshop |
|---|---|---|
| GitHub + GitHub Pages | 13+, no parental-consent path below that ([GitHub ToS](https://docs.github.com/en/site-policy/github-terms/github-terms-of-service)) | Code storage and free hosting; the default "ship" target |
| GitHub Copilot (Education) | Free for verified students 13+; needs academic verification ([GitHub Docs](https://docs.github.com/en/copilot/how-tos/copilot-on-github/set-up-copilot/enable-copilot/set-up-for-students); [Microsoft Learn](https://learn.microsoft.com/en-us/training/modules/embark-ai-journey-free-ai-tools-microsoft-education/improve-coding-skills-github-copilot)) | In-editor AI help; start verification weeks before Session 1 |
| ChatGPT | 13+; under-18s need parent/guardian permission; teen safeguards apply automatically ([OpenAI Terms](https://www.openai.com/policies/terms-of-use/); [TechRepublic](https://techrepublic.com/article/news-chatgpt-teens-safety-gaps/)) | Main conversational AI tutor, named on the permission form |
| Gemini (school accounts) | Available to Workspace for Education students if the district admin enables it ([Google blog](https://blog.google/products-and-platforms/products/education/gemini-iste-2025/)) | Backup if Collierville Schools has it turned on |
| Vercel / v0 | 16+ ([Vercel Terms](https://vercel.com/legal/terms.md)) | Excludes 13–15 year olds; avoid as the default |
| Lovable | 18+ or parental permission ([Lovable terms](https://lovable.dev/terms)) | Avoid |
| Replit | Terms text is ambiguous about minors ([Replit ToS](https://replit.com/terms-of-service-02-23-2026)); live deployment is a paid tier ([Replit pricing](https://docs.replit.com/help/pricing-and-plans.md)) | Not worth the friction |

This reshapes the pitch. "Teens build with Claude" becomes **"teens watch Claude Code build live, then build and ship their own projects with teen-permitted AI."** The demo still shows how agentic AI works in a real build, and teens still use AI on their own projects. Bolt, Cursor, Netlify, and Microsoft Copilot's age terms were not verified, so check each one before naming it on a consent form.

## Set the floor at 13 and plan a separate middle-grade track later

Almost every constraint points to a minimum age of 13. GitHub terminates accounts it discovers belong to under-13s ([GitHub ToS](https://docs.github.com/en/site-policy/github-terms/github-terms-of-service)). ChatGPT starts at 13. Hack Club's "You Ship, We Ship" (YSWS) reward programs, the closest existing model for teen shipping, are generally open to ages 13–18 ([Hack Club YSWS tracker](https://ysws-true-spend.hackclub.com/programs/ysws-hackvault.html)). CLOUD901, the Memphis expansion venue, admits only ages 13–18 ([CLOUD901 Basics](https://www.memphislibrary.org/cloud901/basics/)). The amended COPPA Rule, fully in force since April 22, 2026, is why vendors exclude under-13s in the first place ([Hunton](https://www.hunton.com/privacy-and-cybersecurity-law-blog/coppa-rule-amendment-compliance-deadline-approaches)). Letting 11- and 12-year-olds in would mean a parallel setup with no personal accounts, deploys through someone else's account, and pairing with an older teen. Two volunteer leaders would have to run that alongside everything else.

The research also argues for splitting by age within the 13–18 range. High-retention out-of-school programs **separated activities by age** and gave older teens job-like leadership roles ([Wallace Foundation](https://www.wallacefoundation.org/sites/default/files/2023-08/Engaging-Older-Youth-City-Level-Strategies-Support-Sustained-Participation-Out-of-School-Time.pdf); [Youth Today](https://youthtoday.org/?p=6880)). The recommendation is to group tables as 13–14 and 15–18, and to recruit one or two advanced high schoolers as "junior mentors" with volunteer-hour credit.

The case for including 11–12 year olds is real. Burch Library's Teen Library Ambassadors group covers grades 6–12 ([libnet listing](https://collierville.libnet.info/event/14977780)), and Colonie Library runs a teen-led Python and AI series for grades 6–8 ([Colonie](https://events.colonielibrary.org/event/introduction-python-and-ai-32987)). Serve that age group in a second phase with a separate, account-free AI literacy track built on Experience AI's six-lesson "Foundations of AI" for ages 11–14 ([experience-ai.org](https://experience-ai.org/)) or Day of AI's middle-grades unit ([Day of AI](https://dayofai.org/units/ai-foundations-for-middle-grades)). That track would focus on understanding AI rather than shipping. Keep it out of the pilot.

## Six two-hour sessions that end with a live URL

The design has to deal with one well-documented risk. AI helps novices produce code, but the weakest students are the ones most likely to lose control of it. In a controlled study of 69 learners aged **10–17**, those using an AI code generator had a **1.15x higher completion rate and 1.8x higher scores**, and their ability to modify code by hand did not drop. Learners with more prior experience benefited most ([Kazemitabaar et al., CHI 2023](https://arxiv.org/abs/2302.07427v1)). Prather et al.'s "Widening Gap" study found that struggling novices fell into **"shepherding"** (the AI steers and the student rarely writes code) and **"drifting"** (bouncing between suggestions without progress), while stronger students stayed in control ([ICER 2024](https://arxiv.org/html/2405.17739v1)). Students who used AI to understand code rather than to produce it built deeper understanding ([arXiv 2511.02922](https://arxiv.org/abs/2511.02922v1)). Harvard's CS50 "duck" shows the tutor-not-doer pattern working at scale: questions to human staff fell from **0.89 to 0.28 per student** ([Liu et al.](https://cs.harvard.edu/malan/publications/V1fp0567-liu.pdf)). CS50 also admits its AI sometimes gave away solutions anyway ([SIGCSE 2025](https://rosetta.to/u/cs50/sigcse-2025-improving-cs50-with-ai)).

The countermeasures need no budget and follow from this evidence. First, an **explain-back gate**: no AI-written chunk goes into the project until the student explains it aloud to a partner or leader. Second, a saved **"tutor mode" instruction** that asks the AI for hints and pseudo-code before full code. Third, **driver/navigator pairing** in which the beginner types. Human pairs produced the strongest sense of collaboration in pairing studies ([arXiv 2501.10091](https://arxiv.org/html/2501.10091v2)). Fourth, a short **prompt journal** recording what the student asked, what came back, and what broke. Leaders follow a firm "hands off the keyboard" rule, because a teen leader fixing code for a participant does the same thing as AI shepherding.

Each two-hour session runs the same way: a 15-minute check-in and show-and-tell, a 10–15 minute AI checkpoint, 60–75 minutes of paired building, and a 10-minute deploy plus journal entry. The six-session arc:

| Session | Build goal | AI-literacy checkpoint |
|---|---|---|
| 1. Kickoff | Adult-run Claude Code live demo; accounts and consent checked; a "hello" page live at a URL | "Confident, not correct": catch the AI getting local facts wrong (library hours, a Collierville landmark) |
| 2. Idea and scope | Pick from the project menu; one-sentence pitch; three-feature MVP; first feature | Privacy: what you must never paste into a prompt or collect on your site |
| 3. Build | Core feature; edit AI code by hand before asking for more | Bug bounty: find the subtle bug planted in AI-generated code |
| 4. Build and debug | Debug-first habit (read the error, guess, then ask the AI) | Bias: Teachable Machine or Quick Draw, or ask a model for "a programmer" and discuss who appears |
| 5. Polish and test | Peer user-testing, phone check, README with "AI credits" | Ownership and jobs: who owns AI code, and what the AI couldn't do |
| 6. Demo day | 2–3 minute demos to parents, staff, and local guests | Every demo includes "one thing the AI got wrong" |

The structure combines several sources. A controlled French study found that a single **two-hour AI literacy workshop** improved how 8th and 9th graders used and regulated chatbots on later tasks ([arXiv 2604.01955](https://arxiv.org/html/2604.01955)), which supports a strong Session 1 checkpoint. The Day of AI unit "Truth, Tricks, and AI" ([Day of AI](https://dayofai.org/units/truth-tricks-and-ai-learning-to-verify-information)), Common Sense Education's 15–20 minute lessons ([Colorado DOE listing](https://www.cde.state.co.us/computerscience/computer-science-resource-bank/detail/commonsenseailessons612)), and CodeAI's (formerly Code.org) "How AI Works" videos ([CodeAI](https://code.org/ai/how-ai-works)) fit the checkpoint slot. Several of these are licensed NonCommercial-NoDerivatives. Experience AI, for example, is CC BY-NC-ND 4.0 ([Experience AI doc](https://experience-ai.org/en/drive_resources/137.docx)). Present the originals with attribution rather than publishing edited copies. ALA's 2026 AI guidance asks libraries to teach through a harm-reduction lens without shaming AI users or AI skeptics ([ALA guidance](https://www.ala.org/tools/standards-and-guidelines/guidance-use-artificial-intelligence-libraries)). Frame the checkpoints as "use it well," not "AI is cheating."

**Scope the projects to static web pages.** Use a tiered menu. The default tier, which nearly everyone ships, is a single-page site: a portfolio, a fan page, a quiz, a flashcard tool, a calculator, or a choose-your-own-adventure story. A stretch tier covers browser games and localStorage apps. Chrome extensions and full-stack apps are reserved for advanced high schoolers. Skip anything that needs a backend, login, database, or API key, because keys leak into public repos and data collection creates privacy risk for minors. GitHub Pages is free static hosting with roughly 1 GB of storage, and Netlify Drop lets a student deploy by dragging a folder in, with no git required ([cmaven comparison](https://cmaven.github.io/en/hosting/netlify-vercel-static-hosting-comparison/)). Define "shipped" in Session 1: a public URL that loads on a phone, at least one working interactive feature, and a README saying what the AI did and what the student did. Hack Club learned the cost of a vague standard. Its Arcade program rewarded participation and produced "slop," so its successor program required a real ship ([Why We Ship](https://essays.hackclub.com/why-we-ship/)).

Six sessions is a judgment call. No study compares program lengths. Six leaves room for a real build while limiting the attendance drop-off that free programs face, especially among older teens ([youth.gov](https://youth.gov/shared-resources/engaging-older-youth)). Make each session's goal self-contained and give out catch-up checklists so one missed week does not turn into a dropout. For a four-session version, merge sessions 2–3 and 4–5.

## Burch Library is the host; Hack Club and Rotary are the bank

**Pitch it as a library co-hosted program, not a room rental.** Burch Library's Halle Room seats about 40 and already hosts teen programs. Free use is limited, though: outside organizations pay **$40 per hour** ([Town library document](https://colliervilletn.gov/home/showpublisheddocument/6089/638568324452570000)). A program the library adopts, listed on its calendar with registration through libnet, should avoid that fee. Ask teen services staff for exactly that by calling the main line, 901-457-2601 ([libnet listing](https://collierville.libnet.info/event/13986907)). The library lends a limited number of laptops and encourages attendees to bring their own ([libnet listing](https://collierville.libnet.info/event/13986879)). With **98.7% of Collierville households owning a computer and 97.4% subscribing to broadband** ([Census QuickFacts](https://census.gov/quickfacts/fact/table/colliervilletowntennessee/PST045223)), bring-your-own-device with loaner backup is realistic, and so is homework between sessions. Teen Library Ambassadors meet the first Thursday of each month from 5:30 to 7 p.m. ([libnet listing](https://collierville.libnet.info/event/16716856)). Avoid that slot, and use the group to recruit. Joining when applications reopen gives the organizers formal volunteer standing. The library's projector, Wi-Fi capacity, and rules on minor-led programs could not be confirmed online, so ask about all three in the first meeting.

The pilot needs little money: snacks, printing, certificates, and maybe prizes. **Hack Club** is the best-fit source. Starting a club unlocks **up to $100** of Club Starter funding, and current YSWS programs pay out for exactly this workshop's outputs. "Boba Drops" rewards hosting a workshop where people make a website, and "Swirl" rewards HTML/CSS sites ([hackclub.com/clubs](https://hackclub.com/clubs/)). Those rewards come with a natural quality bar: a public repo and a deployed URL. For tax-deductible donations later, **HCB fiscal sponsorship** through The Hack Foundation is open to teen-led nonprofit projects for a **7% fee** ([hackclub.com/hcb](https://hackclub.com/hcb/)). Locally, the **Collierville Rotary Foundation** runs an annual grant round. The 2026 deadline was September 30, so plan for the 2027 cycle ([Rotary application](https://tally.so/r/2E9qDg)). The Collierville Education Foundation funds only Collierville Schools teachers ([Collierville Schools](https://www.colliervilleschools.org/apps/news/article/1858620)), so its money would have to come through a CHS teacher sponsor. That is another reason to recruit one. Collierville High School already offers AP Computer Science Principles and cybersecurity dual enrollment ([CHS course page](https://colliervillehs.colliervilleschools.org/56862_3)), and those teachers are the likeliest sponsors and recruiters. Collierville Schools also publishes AI-use guardrails ([colliervilleschools.org/ai](https://colliervilleschools.org/ai)), which are worth reading before promoting through schools.

Two partnership precedents strengthen the pitch. Multi-week, teen-led, ship-a-project library programs are rare. Most 2026 library AI programs were one-off sessions, such as Weston's "Learn about Vibe Coding" for ages 13+ ([Weston PL](https://westonpl.librarycalendar.com/event/learn-about-vibe-coding-5915)). East Lansing's "Teens Vibe Coding for the Community" had teens build apps for local problems ([ELPL](https://elpl.bibliocommons.com/events/69b20c3ab48451fc3c084cc5)). That is a strong project theme for Collierville. **CodeCrew**, Memphis's main youth coding nonprofit, already teaches AI and has run camps at Memphis Public Libraries ([Eventbrite](https://www.eventbrite.com/e/codecrew-after-school-fall-2026-registration-1993338930400); [MPL calendar](https://memphis.librarycalendar.com/event/code-crew-data-design-camp-9895)). Present the workshop as a suburban, short-format complement to CodeCrew and a pipeline into its programs, not a competitor.

## Paperwork keeps the library, not the teens, holding the data

The organizers are minors running a program for minors. The cleanest setup is that **the library holds every form and a staff member or vetted adult sponsor attends every session.** The organizers should not collect or store parent data themselves. No national standard covers minors leading library programs or background checks for adult sponsors, so these are local Town of Collierville decisions to raise up front. ALA guidance says staff and volunteers serving minors should be trained on privacy and confidentiality ([ALA K-12 Privacy Checklist](https://www.ala.org/advocacy/privacy/checklists/students)).

The packet has five parts: the library's own program registration; a **parent/guardian permission form that names each tool, its age rule, and the account the teen will create or use** (required for ChatGPT under 18 and good practice for GitHub); an opt-in **photo/media release**; emergency contact and pickup details; and a teen code of conduct with an AI acceptable-use pledge. Use library templates wherever they exist. Nearby Tipton County Public Library, for example, publishes photos of minors only with a signed parent release ([Tipton County policy](https://tiptoncountylibrary.org/wp-content/uploads/2024/10/photo091624.pdf)). Tennessee had no law specifically regulating minors' use of AI chatbots as of November 2026. The 2026 CHAT Act was reduced to a state study ([AI Laws USA](https://ailawsusa.com/protection/tn-tacir-ai-chatbot-regulation-study-pc1082-2026/)), and the state's social media age-verification law targets social media platforms, not coding tools ([TN Attorney General](https://www.tn.gov/attorneygeneral/news/2026/2/4/pr26-7.html)). The legal exposure that matters is in the teens' own projects. A site that collects personal information from children could make its builder a COPPA operator. So the rules taught in Session 2 are also the safety policy: no real names, schools, addresses, photos, or passwords in prompts; no sign-up forms or analytics on teen sites; no API keys in code or repos; training opt-outs turned on where available; and an adult checks every site before it is shared publicly. These match the safeguards Anthropic itself requires of products serving minors ([Anthropic minors guidelines](https://support.claude.com/en/articles/9307344-responsible-use-of-anthropic-s-models-guidelines-for-organizations-serving-minors)).

## Measure behavior, not just smiles, and Memphis will listen

Funders want numbers, and the research shows which ones mean something. Track **reach** (registrations, unique attendees, grade mix, share of first-time coders), **engagement** (attendance per session and the share attending at least 75% of sessions), and **output**: the share who shipped a URL meeting the definition, collected in a public gallery page, plus the demo-day audience count. For attitudes, use a 5–8 item **retrospective pre/post** survey ("before this program I… / now I…"). A maker-program study found that youth misjudge their own change on traditional separate pre and post surveys ([ASEE PEER](https://peer.asee.org/24064.pdf)). The PEAR Institute's 14-item Common Instrument measures STEM engagement in about five minutes ([NSTA](https://www.nsta.org/connected-science-learning/connected-science-learning-july-september-2019/common-instrument-suite)), but whether it is free for small programs was not confirmed. The critical-AI goal needs a behavioral measure. In the French study, behavior captured the workshop's effect while self-reported attitudes did not ([arXiv 2604.01955](https://arxiv.org/html/2604.01955)). Score each demo-day presenter on two things: can they explain one function they shipped, and can they name a specific error the AI made and how they caught it? No validated teen AI-literacy instrument turned up in this research, so that rubric is the most credible substitute. Keep surveys anonymous and covered by parent consent.

Those numbers are the ticket to Memphis, and the expansion needs a different design. **CLOUD901**, on the first and second floors of the Central Library at 3030 Poplar, is a free lab for ages 13–18. It has hosted a coding workshop for ages 13–15 presented by White Station High School students ([CLOUD901 Basics](https://www.memphislibrary.org/cloud901/basics/); [MPL calendar](https://memphis.librarycalendar.com/event/white-station-high-school-presents-coding-workshop-ages-13-15-29709)), and its listed programs show no dedicated AI offering. The entry path runs through CLOUD901 staff and the MPL volunteer process, which includes training and background checks ([volunteer portal](https://volunteer.memphislibrary.org/vrcnominationform)). Eight branches host Teen Innovation Centers, including Cordova, the closest to Collierville ([Teen Innovation Centers](https://www.memphislibrary.org/teen-innovation-centers/)). The **Memphis Library Foundation**, which sponsors 2026 CLOUD901 programs, is the obvious funder to approach with pilot results ([MPL calendar](https://memphis.librarycalendar.com/event/cloud901-dj-camp-46952)). The AutoZone Foundation and the Community Foundation of Greater Memphis are the larger follow-ups ([Shareway AutoZone](https://www.theshareway.com/grant/autozone-foundation-22816-greater-memphis-area-grants); [Shareway Give 365](https://www.theshareway.com/grant/community-foundation-94693-give-365-memphis-grants)). The design change is about connectivity. Shelby County's household broadband rate is **89.6%** ([Census QuickFacts](https://www.census.gov/quickfacts/fact/csv/shelbycountytennessee/COM100224)), and about half of Memphis city households lacked broadband in older 2016 data ([Memphis Flyer](https://memphisflyer.com/NewsBlog/archives/2018/06/14/report-half-of-memphis-homes-not-connected-to-broadband)). The Memphis version should keep all work in-session on library or loaner devices with browser-only tools and no homework. Netlify Drop and GitHub's web editor fit that model.

## Conclusion

The age rules look like a blocker, but they push the workshop toward a better design. Teens can't hold Claude accounts, so the program has to separate watching an expert agent build (the adult-run Claude Code demo) from building yourself with tools you can legally keep using after the workshop ends. A teen who leaves with a GitHub account, a live site, and the habit of explaining every AI-written line has something more durable than a borrowed login. The 13+ floor and static-site scope are also exactly what makes the Hack Club rewards, the CLOUD901 venue, and a low-risk privacy posture all fit together.

The open questions are local. Will Burch Library co-sponsor a program led by minors? Who serves as the adult in the room? Does Claude for Teachers allow any supervised student interaction? The first meeting with teen services staff and a CHS teacher can settle all three. One more gap matters for anyone who later studies this program: no research yet covers teens using agentic coding tools outside school. Collecting explain-back scores and "AI got it wrong" examples from the pilot would produce some of the first real data on that question.
